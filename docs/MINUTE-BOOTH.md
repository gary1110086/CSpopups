# 60秒任务挑战 / One Minute

从一分钟挑战进入。随机抽题或自己选题，读完后开始。题目网站、倒计时和结果都在同一个浏览器标签页。

- [一分钟挑战](https://gary1110086.github.io/CSpopups/browse/booth.html?lang=zh&v=booth5) · [One Minute](https://gary1110086.github.io/CSpopups/browse/booth.html?lang=en&v=booth5)

## 工作人员怎么用

1. 正式挑战直接选题或随机抽题。想先试题目难度，在选题页底部展开「工作人员工具」并进入「难度测试 · 无广告」。这里也可以打开自由浏览、查看最近轮次，或将进阶题加入随机抽题。
2. 让参与者读完题目及完成条件，再点击开始。读题期间不计时。
3. 网站首次可操作后开始60秒。浏览、搜索、详情、刷新、返回以及广告标签页消耗的时间都算在同一轮中。顶部有“查看任务”和“我完成了”。
4. 到时自动在原任务标签页显示结束页；也可提前交卷。若参与者正在广告标签页，工作人员提示返回原任务页。浏览器后台调度可能延迟画面切换，恢复后按原截止时间立即结束，不补时间。
5. 结果页先显示截止前记录到的收藏、参数和导出证据。展开「工作人员 · 核对与交接」查看答案和路线，再选择已完成、部分完成或未完成。点击「查看本轮复盘」可以回看本轮广告互动。导出记录可与实际下载文件一起核对。
6. 关闭本轮广告标签，在「工作人员 · 核对与交接」里确认，再点击「下一位」。新一轮有独立的收藏与任务状态，旧记录仍可在工作人员工具中查看。

来源、图片署名与其他辅助说明会另开原生标签，原任务页的60秒继续计时。

网站内的工作人员按钮可以因加载/设备问题作废本轮。作废单独标记。查看任务或进入其他标签不会暂停挑战；Escape处理广告，不能重开60秒。

## 广告节奏与难度试跑

每题使用一组虚构校园推广。前台约 4.5 秒出现一张小型静音广告，前 10 秒最多一张。之后每约 2–3 秒可出现一张，约 13 秒出现顶部广告条。浮窗同时最多四张，手机最多两张。达到上限时暂停增加。广告可能模仿这道题的筛选、对比或导出按钮。真正的关闭按钮清晰可见，部分广告另有会打开推广页的假叉。

45–55 秒是首次游玩、正确完成的设计目标。试跑时给未见过题目的同学指定关卡，读完再开始，过程中不给路线提示。分别记录有广告和无广告的用时、完成状态、卡住的步骤，以及是否误开推广页。按题看正确完成的中位用时和超时比例，再决定调整题目线索还是广告密度。同一位同学用两种模式试玩时，给不同的题以减少记忆路线带来的影响。

## 导出与结果的边界

导出条件要求在截止前成功生成文件，并发起下载请求。仅点击按钮、编码仍未完成，不算完成；到时不额外延长，异步回调不得补记。工作人员可检查实际下载文件。取消收藏或改错份量会撤销相应机器条件；提前交卷本身不代表答对。

本轮观察保留在当前标签页的sessionStorage中，不跨电脑同步。结果/复盘可分别导出TXT。轮次索引最多保留12轮；旧的广告观察记录沿用其独立数量上限。

## 本地运行

```sh
python browse/preview-server.py --port 5210
```

打开 `http://127.0.0.1:5210/browse/booth.html?lang=zh&v=booth5`。需从仓库根目录提供共享的 assets 与 wallpapers 资源。

GitHub Release 中的 cleaner1 ZIP 对应早期版本。本轮试玩使用上方入口或当前仓库源码。

普通Browse自由浏览、早期Little Daily和独立Stillwall继续使用各自原来的流程；它们不会因为活动版新增而自动限时。
